THE THESIS

Three failures, three guarantees

Running one agent on one task is solved. Running dozens over months, on your own memory and files, is where things go wrong: you get pushed along, you learn nothing, and work scatters.

Asteria is a workbench for one person building with AI. Everything is a plain, searchable, traceable file. Any part can be swapped whole without shaking the rest. Before a decision is signed, the work pauses and the decision becomes something learned. Success is measured, not felt.
Plain files

Markdown and config are the only durable form. Nothing lives in a store that the files could not rebuild.

Swappable parts

Dependencies point one way, paths live in one config, every contract ships with a check that can fail.

Pause before signing

A triage gate decides which decisions reach the human; the loop freezes there and the decision becomes a lesson.

FIVE IDEAS

What carries the design

01

A human signs, by rule not by feel

Which decisions reach the human is computed from three inputs: will it recur, how much does it touch, can it be undone. At most one learning side quest per session.

Human in the loop
02

Tiered memory, proposals at the top

Session memory is disposable, project memory is working state, persistent memory is canon. Nothing writes to canon directly: agents file proposals, the human approves.

Memory and errata
03

Errata are checks, not advice

A failure that repeats becomes an entry and a write-time check that blocks. A warning that cannot block is theater: blocking fires every time, advisory fires never.

Memory and errata
04

Producer is never verifier

The agent that wrote it does not grade it. Verification comes from a test run, a fresh context, another model or a human: a signal the producer did not have.

Simplicity and search
05

Simplicity is a goal, never a criterion

"Is this simple enough?" is banned at the gate. Gates ask only what a command can answer: diff size, exit codes, counts. Simplicity is read off afterwards.
